# PPTX 조판 규칙

이 문서는 amorepacific-presentation 스킬로 `.pptx`를 만들 때 Claude가 따르는 조판 규칙입니다. 폰트가 설치된 환경과 설치되지 않은 생성 환경 사이에서 글자 폭이 달라지면, 줄바꿈 위치와 텍스트 박스 배치가 생성 시점과 다르게 보입니다. 이 문서는 그 차이가 생겨도 문구가 깨지거나 요소가 겹치지 않도록 박스를 설계하고 검수하는 방법을 정합니다. HTML 슬라이드에는 적용하지 않으며, HTML 디자인 규칙은 `SKILL.md`와 `reference.md`를 따릅니다.

## 1. 언제 PPTX를 만드는가

기본 산출물은 페이지 전환형 단일 HTML 프레젠테이션입니다. PPTX는 사용자가 "PPT", "PowerPoint", "파워포인트", "PPTX"처럼 파일 형식을 명시했을 때만 만듭니다.

| 요청 표현 | 산출물 |
|---|---|
| "PPT로 만들어줘", "PPTX로 뽑아줘", "파워포인트 파일로" | `.pptx` (이 문서 적용) |
| "PPT처럼", "슬라이드처럼", "발표자료로" | 페이지 전환형 HTML |
| 형식 언급 없음, 또는 형식이 불명확함 | 페이지 전환형 HTML |

"PPT처럼"은 화면 구성 방식을 말한 것이지 파일 형식을 지정한 것이 아니므로 HTML로 해석합니다. 형식이 애매할 때 PPTX를 고르면 폰트 환경 문제를 떠안게 되므로 HTML을 기본값으로 둡니다.

## 2. 폰트 지정

- 모든 한글 텍스트에 아리따 돋움(Arita Dotum KR)을 지정합니다. 영문·숫자도 같은 서체로 지정해 한 줄 안에서 서체가 섞이지 않게 합니다.
- PowerPoint는 한글을 동아시아 글꼴 슬롯(`<a:ea typeface>`)으로 그립니다. 라틴 글꼴(`<a:latin>`)만 지정하면 한글은 테마 기본 글꼴(맑은 고딕 등)로 바뀌므로, 런마다 `latin`과 `ea`를 둘 다 지정합니다. python-pptx의 `font.name`은 `latin`만 바꾸므로 `ea`는 XML로 따로 넣어야 합니다.
- 제목과 강조 문구는 아리따 돋움 Bold로 씁니다. 아리따는 굵기마다 서체 이름이 따로이고 Regular가 없습니다(2026-10-13 맥 설치본에서 확인). 그래서 본문은 `Arita Dotum KR Medium`, 제목·강조는 `Arita Dotum KR Bold` 이름으로 지정하고 bold 속성은 켜지 않습니다. 속성까지 켜면 PowerPoint가 한 번 더 굵게 그립니다. `slide-to-pptx` 스킬의 변환 스크립트도 같은 방식입니다.

```python
from pptx.oxml.ns import qn

def set_arita(run, bold=False):
    """런의 라틴·동아시아 글꼴을 모두 아리따 돋움으로 지정한다."""
    face = "Arita Dotum KR Bold" if bold else "Arita Dotum KR Medium"
    run.font.name = face          # <a:latin>
    run.font.bold = False         # 굵기는 서체 이름으로 준다
    rPr = run._r.get_or_add_rPr()
    ea = rPr.find(qn("a:ea"))
    if ea is None:
        ea = rPr.makeelement(qn("a:ea"), {})
        rPr.find(qn("a:latin")).addnext(ea)  # 스키마 순서: latin → ea → cs
    ea.set("typeface", face)
```

### 대체 폰트로 잰 폭은 믿지 않는다

생성 환경(Claude의 샌드박스, CI, LibreOffice 등)에는 아리따가 없는 경우가 많습니다. 이때 미리보기와 폭 계산은 Pretendard·Noto Sans KR 같은 대체 폰트로 이뤄집니다. 아리따는 자간이 넓은 서체라서 같은 문구라도 대체 폰트보다 길어질 수 있습니다.

- 대체 폰트로 계산한 텍스트 폭을 실제 아리따 폭과 같다고 가정하지 않습니다.
- 대체 폰트 렌더링은 요소 겹침, 슬라이드 밖으로 나간 요소, 명백한 넘침을 찾는 참고용으로만 씁니다.
- 아리따가 없는 환경의 미리보기를 최종 조판 검증 결과로 보지 않습니다. 줄바꿈이 맞아 보여도 "아리따에서도 맞는다"는 근거가 되지 않습니다.

생성 환경에 아리따가 있는지는 추측하지 말고 확인합니다.

```bash
fc-list | grep -i "arita" || echo "아리따 없음"
```

## 3. 줄바꿈

배치가 중요한 텍스트는 PowerPoint의 자동 줄바꿈에 맡기지 않습니다. 자동 줄바꿈은 글자 폭에 따라 끊는 위치가 바뀌므로, 폰트 환경이 달라지면 다른 문장이 됩니다.

- 제목, 핵심 메시지, 강조 문구, 캡션은 의미 단위로 줄을 직접 나눕니다.
- 두 줄 이상인 중요 문구는 한 박스에 넣지 않고, 줄별 또는 문장별로 독립된 텍스트 박스에 둡니다. 한 줄이 아리따에서 길어지더라도 그 줄만 영향을 받고 다음 줄의 위치는 바뀌지 않습니다.
- 사용자가 준 줄바꿈은 그대로 유지합니다. 글자 수를 맞추려고 임의로 줄을 합치거나 옮기지 않습니다.
- 자동 줄바꿈은 짧은 본문처럼, 어디서 끊겨도 뜻이 상하지 않는 텍스트에만 허용합니다.
- 조사, 닫는 괄호, 문장부호, 기호, 영어 단어 하나가 다음 줄에 홀로 남지 않게 끊습니다. 줄 끝이 조사로 끝나고 다음 줄이 명사로 시작하도록, 즉 어절 경계에서 끊습니다.

잘못된 방식은 좁은 박스 하나에 긴 문장을 넣고 줄바꿈을 PowerPoint에 맡기는 것입니다.

```text
[하나의 좁은 박스]
혼자 고민해봤는데, 남이 어떻게 일하는지부터 봐야겠더라고요.
```

권장 방식은 의미 단위마다 박스를 나누는 것입니다.

```text
[박스 1] 혼자 고민해봤는데,
[박스 2] 남이 어떻게 일하는지부터 봐야겠더라고요.
[박스 3] 그래서 여러분을 관찰(?)하기로 했습니다.
```

이렇게 나눈 박스는 `word_wrap = False`로 두어 박스 안에서 다시 줄이 바뀌지 않게 합니다.

## 4. 텍스트 박스 설계

폭과 높이는 대체 폰트에서 잰 값에 여유를 더해서 정합니다. 아리따에서 길어질 몫을 미리 확보하는 것이 목적입니다.

| 항목 | 기준 |
|---|---|
| 박스 폭 | 대체 폰트로 잰 최소 폭보다 15-20% 넓게 |
| 텍스트 점유율 | 박스 폭의 85% 미만 |
| 박스 높이 | 실제 줄 수에 필요한 높이보다 20% 이상 여유 |
| 내부 여백 | 상하좌우 inset을 폭·높이 계산에 포함 |
| 긴 강조 문구 | 좌우 여백이 있으면 슬라이드 전체 폭에 가까운 박스 사용 |

높이는 `줄 수 × 글자 크기 × 행간 + 상하 inset`으로 계산한 뒤 20%를 더합니다. inset을 빼고 계산하면 마지막 줄이 박스 밖으로 밀립니다.

문장이 길어서 박스에 들어가지 않을 때는 글자부터 줄이지 않고 다음 순서로 조정합니다. 글자를 줄이면 슬라이드마다 글자 크기가 달라져 위계가 무너지기 때문입니다.

1. 문구를 짧게 다듬습니다.
2. 의미 단위로 줄바꿈을 넣습니다.
3. 텍스트 박스 폭을 넓힙니다.
4. 텍스트 박스 높이를 늘립니다.
5. 그래도 안 될 때만 글자 크기를 줄입니다. 이때도 `reference.md` 4.2 PPT Type Scale의 범위 안에서 줄입니다.

## 5. 자동 맞춤 끄기

PowerPoint의 "넘치면 텍스트 크기 조정(Shrink text on overflow)", AutoFit, 자동 글자 축소를 쓰지 않습니다. 자동 축소는 폰트 환경마다 다른 크기로 글자를 줄이므로, 넘침을 숨길 뿐 해결하지 않습니다.

- 제목과 핵심 메시지는 자동 맞춤을 항상 끕니다.
- 본문도 원칙적으로 끄고, 설계 단계에서 확보한 박스 안에 들어가게 맞춥니다.
- python-pptx에서는 `text_frame.auto_size = MSO_AUTO_SIZE.NONE`으로 두고, `bodyPr` 안에 `normAutofit`이나 `spAutoFit`이 남지 않게 합니다.

## 6. 레이아웃 안정성

폰트 차이로 문구가 한 줄 늘어나도 아래 요소와 겹치지 않게 배치합니다.

- 중요 문구 아래에 다른 요소를 이어 놓을 때는 위 박스의 실제 렌더링 높이에 기대지 말고, 고정 좌표와 충분한 간격으로 둡니다.
- 인접 요소 사이에 최소 0.15-0.25인치의 안전 여백을 둡니다. 한 줄이 늘어나는 경우까지 견디려면 이 여백이 그 줄 높이보다 커야 하므로, 큰 글자 아래에서는 0.25인치 쪽을 씁니다.
- 제목, 부제, 설명, 주석을 한 박스에 넣지 않습니다. 각각 독립된 텍스트 박스로 만듭니다.
- 작은 주석과 출처는 본문 박스에 합치지 말고 별도 박스로 둡니다. 본문이 늘어나도 주석 위치가 움직이지 않게 하기 위해서입니다.

## 7. 검수

PPTX를 만든 뒤 아래 항목을 확인합니다. 글꼴, 자동 맞춤, 경계 이탈은 파일을 직접 읽어서 확인하고, 겹침은 렌더링해서 봅니다.

- [ ] 모든 한글 런에 아리따 돋움이 `latin`과 `ea` 양쪽에 지정되어 있다
- [ ] 사용자가 의도한 줄바꿈이 그대로 유지되어 있다
- [ ] 제목과 강조 문구가 자동 줄바꿈에 의존하지 않는다(`word_wrap = False`, 명시적 줄 구성)
- [ ] 두 줄 이상인 중요 문구가 줄별 독립 박스로 구성되어 있다
- [ ] 자동 맞춤과 자동 축소가 켜진 박스가 없다
- [ ] 텍스트 박스 폭에 최소 15%의 안전 여백이 있다
- [ ] 아리따가 없는 환경의 렌더링 결과를 실제 아리따 조판과 같다고 보지 않았다
- [ ] 박스 밖 텍스트, 요소 겹침, 슬라이드 경계 이탈이 없다

글꼴과 자동 맞춤은 아래 코드로 한 번에 훑을 수 있습니다.

```python
from pptx import Presentation
from pptx.oxml.ns import qn

prs = Presentation("deck.pptx")
W, H = prs.slide_width, prs.slide_height
for i, slide in enumerate(prs.slides, 1):
    for sh in slide.shapes:
        if sh.left + sh.width > W or sh.top + sh.height > H or sh.left < 0 or sh.top < 0:
            print(f"{i}: 경계 이탈 {sh.name}")
        if not sh.has_text_frame:
            continue
        body = sh.text_frame._txBody.find(qn("a:bodyPr"))
        if body.find(qn("a:normAutofit")) is not None or body.find(qn("a:spAutoFit")) is not None:
            print(f"{i}: 자동 맞춤 켜짐 {sh.name}")
        for p in sh.text_frame.paragraphs:
            for r in p.runs:
                rPr = r._r.find(qn("a:rPr"))
                ea = rPr.find(qn("a:ea")) if rPr is not None else None
                if any("가" <= c <= "힣" for c in r.text) and (
                        ea is None or not ea.get("typeface", "").startswith("Arita Dotum KR")):
                    print(f"{i}: 한글 ea 글꼴 누락 {sh.name} {r.text[:20]!r}")
```

### 최종 응답에 남길 문장

검수 환경에 아리따가 없으면 최종 응답에 아래 문장을 그대로 짧게 붙입니다. 받는 사람이 미리보기와 실제 조판의 차이를 알고 PowerPoint에서 한 번 더 확인하도록 하기 위해서입니다.

> PPTX에는 Arita Dotum KR이 지정되어 있습니다. 현재 생성 환경에는 해당 폰트가 없어, 대체 폰트 미리보기는 레이아웃 참고용으로만 검수했습니다. 중요 문구는 명시적 줄바꿈과 여유 박스를 적용했습니다.
